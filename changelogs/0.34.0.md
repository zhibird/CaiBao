# v0.34.0 · 一起把事情逐步做好

彩宝现在可以维护一份按任务保存的工作计划：API 通过有界的 `update_plan` 控制工具更新，Codex 与 Claude Code 投影已经返回的原生任务事件。桌宠当前任务、断线恢复和只读历史展示同一份记录，并明确说明步骤状态由模型报告。

承接 v0.29 的后台任务记录、v0.31 的跨后端身份和 v0.33 的执行回执，本次补上动态工作安排。原有执行结果仍由运行器记录，计划属于独立的模型报告。

## 计划与执行分别记录

- 计划卡展示待处理、模型标记进行中／完成／取消以及公开调整说明。任务结束、失败或停止后保留最后快照，不自动把步骤勾完；勾选不改变执行回执、任务终态、表情或朗读。
- 普通问候、一次查询和只要求计划文本时可直接回答；聊天模式继续不开放控制工具。复杂任务才鼓励维护步骤。
- 每份快照最多10项、每项160字、最多一项进行中，所有内容按纯文本显示。来源由运行器固定，模型不能指定任务、用户或来源，也不能把计划文字当命令执行。

## 有限规划，审批不断账

API 计划更新与外部工具动作分别计数。每轮最多8次计划尝试，无效参数和重复内容也计入；相同快照不会刷版本。外部额度耗尽后仍可在剩余额度内收尾计划，计划更新不会伪装成工具成功、失败或遗漏。

API 工具循环最多15次模型调用，包含最后一次禁用工具的总结，审批续跑共用原次数；前置检索与底层网络重试不计入该循环上限。检查点保留原始请求批次，同批并行工具不会误当成多次模型请求；计数、版本或批次证据损坏时拒绝执行。私有批次标记在发送给模型前剥离。旧审批保守恢复并可继续后续审批，不给循环添加次数。

独立审计修复了超额计划提议使合法审批锁死、模型次数回退后重新获得额度，以及嵌套私有标记被发给提供商的问题。过量元数据同一批只记录一次额度拒绝，避免放大写入，同时保留有效外部调用。

## 原生 CLI 与持久化

Codex 接收 `todo_list` 的开始、更新与结束事件。上游只有文字和完成布尔值，未完成不能被猜成进行中，列表事件结束也不代表所有步骤完成。

Claude Code 按真实工具调用 ID 配对 `TaskCreate/TaskUpdate` 及旧 `TodoWrite`，创建使用实际结果 ID，更新验证结构化成功、ID 和更新字段。失败、未知任务、歧义和无结果的提议不制造进度。只追踪本次执行实际观察到的任务；Pi 没有默认计划事件时不从自然语言猜测，也不为展示改变 CLI 权限或命令参数。

快照通过运行状态和旧值的条件写入保存，终态后的迟到更新不能覆盖记录。CLI 展示达到64份不同快照后明确冻结并保留最后记录；下一轮任务独立开始。新增可空列和迁移兼容旧任务，原数据与执行回执保留。
