# v0.29.0 · 任务留在后台，回来接着看

把排队任务从浏览器连接中独立出来。彩宝执行任务时，刷新、断线或关闭观察页面不会重新执行；重新打开后从持久记录接回进度。

## 新增

- 后台运行器拥有自己的数据库会话，采用有界线程池与队列；多个观察者共享同一份执行和事件记录。
- 持久事件游标、SSE 心跳、断线续接及只读任务历史。历史中的未启动任务不会因为查看而开始执行，恢复的旧回复也不会自动朗读。
- 稳定的提交标识：创建响应丢失后沿用原标识重试，相同参数返回原任务；同标识更改参数会被拒绝。
- 跨服务进程的任务租约、独立续租，以及同一对话的托管 CLI 会话互斥。过期任务留下中断记录，保留已知结果，不自动重放可能已发生的操作；旧 CLI 仍可能存活时，继续保留会话占位。
- 桌宠审批令牌绑定当前操作与模型回合，旧按钮和迟到重试不能授权下一次写入，即使两次内容完全一致。审批执行也独立于 HTTP 观察者。
- 桌宠刷新后发现进行中的任务，恢复文字、工具步骤及当前审批；结果尚不确定时阻止重复提交，并提供重新核对入口。切换账号后旧回调不再写回当前界面。

## 修复

- 流式回复的最终历史按原始文字片段拼接，不再在每个片段之间多插入换行。
- 确认操作完成后更新原任务的聊天记录，避免历史停留在“等待确认”。
- 模型或工具初始化失败、未完成执行便结束、排队期间关闭服务等情况都留下明确终态，避免永久显示“进行中”。
- 非 ASCII 的错误审批令牌正常被拒绝，不再触发服务端异常。

## 验证与范围

本机全仓 Python 测试 **733 passed、3 skipped**；前端任务恢复、SSE 和朗读文本测试 **20 项通过**。覆盖并发幂等提交、观察者断开、跨运行器认领、慢工具续租、CLI 会话互斥、租约过期、清理顺序、真实测试子进程关闭、只读历史及审批竞争。数据库迁移完成升级、降级、再升级检查。

浏览器在后台核对了恢复界面与小窗口布局；原生应用通过 Swift 编译、plist 与本地签名验证。遵照用户要求，整个模块收尾没有重新弹出桌宠。测试使用假模型和模拟 CLI，没有配置或调用真实 DeepSeek，也没有使用订阅额度。

可靠恢复目前覆盖排队／托管任务链路，原有同步入口保留兼容行为。取消仍在模型与工具边界协作生效，已经开始的外部调用可能完成；事件日志暂时全部保留，尚未加入自动清理。CLI 原服务永久丢失时仍保留旧对话占位，可以新建对话使用独立工作区，尚未自动回收遗留 CLI。详见 [任务生命周期设计](../docs/agent-task-lifecycle.md) 与 [桌宠使用说明](../docs/companion.md)。
