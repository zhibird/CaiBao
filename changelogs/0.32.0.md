# v0.32.0 · 说句话，彩宝在听

macOS 桌宠新增显式语音输入：点麦克风说话，再点结束。设备端识别完成后，文字先进入可编辑草稿，确认发送才交给原有 Agent；不靠语音直接绕过工具审批。

## 语音回合

- 启动时不申请权限、不打开麦克风。首次主动使用时才请求语音识别和麦克风授权，检查中文设备端模型；不支持、未授权或设备异常时明确提示，不自动改用云端或浏览器识别。
- 每轮最多30秒录音，结束后最多5秒等待最终文字；只返回 final，空结果、超时与超长内容明确失败，已有草稿不变。
- 识别文字追加到最新草稿，保留录音期间的手工编辑。草稿容量不足时完整保留本次文字供复核，缩短草稿后再加入；没有静默覆盖或截断。
- 朗读与录音互斥，表情区分等待授权、正在听和整理文字。录音期间禁止发送，完成后仍由用户确认；既有 Agent 运行、审批、记忆和后端切换规则继续适用。
- 普通浏览器保留其支持的语音入口，先说明可能由浏览器提供商远程处理，再由用户确认。此入口与原生设备端识别区分，不作为原生失败的备用通道。

## 生命周期

隐藏、收起、退出、重新连接、导航和应用失活会清理原生录音。网页切换账号、对话、页面状态或输入场景也会取消回合；回合标识与内部代次拒绝迟到权限、识别和计时器回调，不能把旧录音写入新草稿。

音频输入 tap 绑定原始识别请求，结束后关闭追加、停止引擎、移除 tap，再取消识别任务并释放引用。没有新增音频文件存储或音频上传接口；确认发送后的文字仍按所选模型处理。

## 验证

32 项纯 Foundation 原生测试、84 项前端测试、92 项桌宠相关 Python 检查通过。原生测试采用假的权限、录音、识别和时钟，覆盖拒绝、设备端不可用、30／5秒上限、重复请求、迟到事件、取消与重试。独立无界面浏览器验证18个隔离页面场景，确认识别过程没有任务写入，用户点击发送后只创建一次任务，并验证440×740布局与原生无参数导航回归。macOS 应用完成编译、plist 和本地签名验证，CI 加入原生语音生命周期检查。

开发过程没有启动桌宠、请求设备权限、录制真实音频或调用真实模型。真实设备的中文识别准确率、本地语音模型与首次授权提示，留待用户之后主动使用时验收。更多说明及一手参考见 [语音回合说明](../docs/companion-voice.md)。
