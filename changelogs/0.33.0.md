# v0.33.0 · 做了什么，如实说

修复两处 Agent 核心问题：工具失败却把任务标成完成，以及多次审批续跑反复获得整份预算。API 工具循环现在共用整轮执行账本，以实际返回结果归纳失败或部分成功，桌宠当前任务和历史记录显示独立执行回执。

## 可信的执行事实

- 同步、流式和审批续接使用同一个工具循环。失败、拒绝、预演、尚无结果的预留与明确略过的提议分别计数，不能因为模型停止输出就抹掉失败。
- 每次工具提议先占用一次预算；危险动作等待审批时已经预留，确认只结算本次，不重置计数或重复调用保护。同一审批重复确认不会再次执行或扣减。
- 达到预算后禁用工具并收尾；提供商继续提议也不执行。恰好用完且没有已知错误、遗漏的任务允许正常结束；明确未执行的额外提议、重复保护与循环上限都会留下原因。
- 损坏 JSON、顶层字符串／数组和未启用工具明确拒绝；流式参数只在执行门口解析，不再用空对象替代错误参数。MCP 明确错误标志也计为失败，网络传输成功不等于工具成功。
- 工具已运行后再遇到提供商不支持函数调用，不转入关键词备用路径重复做事；首次不支持且没有执行工具时，真正备用流程仍可使用。

## 审批与恢复

新审批保存预算、计数和私有重复签名。旧记录只从成对 assistant/tool 事实重建；损坏记录、预算不符、缺失检查点都拒绝执行，不给任务添加次数。删除检查点也不能把真实函数调用审批伪装成关键词备用审批。

回执随任务查询与终态事件保留。取消、中断和外层异常按权威运行状态呈现；「等待审批」与「已开始但结果尚未确认」分开，不能把不明动作说成从未执行。外层失败也写入正式会话记录，保留本次失败上下文。

## 桌宠回执

当前任务与只读历史使用同一份公开快照，仅显示白名单计数和停止说明，不展示私有参数、签名或原始错误。旧任务、CLI 和工作流未记录 API 回执时明确说明，不猜测预算。正常完成提示改为「回复已返回」；工具返回仍不构成外部业务目标已验证的证明。

## 验证与范围

本机 Python 全仓 **1032 passed、3 skipped**；前端 **109 项通过**。新增34项真实认证、运行器与数据库入口回归，覆盖工具失败／部分成功、跨审批预算与重复保护、损坏证据、合法备用流程、MCP 错误标志和失败事件回执；执行账本、严格公开类型和迁移往返另有独立测试。后台实际页面8组验收通过，核对恢复、历史只读、回执来源、隐私与440×740窗口的完整回复和发送入口；修复先恢复后展开的滚动竞态，以及当前回执与历史同时查看时的高度挤压。macOS 应用完成编译、plist 与本地签名验证。

测试采用假模型和隔离数据，没有消耗真实模型或订阅 CLI 额度，也没有打开桌宠窗口。本模块的预算与回执覆盖 API 函数调用循环；CLI、工作流和关键词备用路径保留各自规则。更多含义、一手参考和边界见 [可信执行说明](../docs/agent-execution-receipts.md)。
