# 彩宝这一轮实际做了什么

API Agent 的「执行回执」记录运行器观察到的工具结果和停止原因。它与模型的回复分开：模型说「工具失败」时，系统不能又显示成功；模型说「完成了」，也不能把这句话当成外部业务已经验证的证据。

桌宠当前任务和只读历史共用同一份回执。任务正常结束时提示「回复已返回」，有失败或已知未执行的提议时提示核对。回执不包含内部思维、工具参数或原始错误，只显示次数和固定原因说明。旧任务没有回执就明确标为未记录，不从当前设置推测过去。

## 一轮任务，一份预算

`max_steps` 对 API 函数调用循环表示本次运行的工具尝试上限，桌宠默认6次。同步、流式和审批续跑共用同一账本；刷新、重连、查看历史、重复点击确认都不会给任务添加次数。

一次已接纳的工具提议先占用预算，再调用处理器或等待审批。未知工具、未启用工具和参数不合法的提议也消耗一次尝试，防止无效提议无限循环；不会因此真正执行工具。JSON 必须只解析为对象，损坏 JSON 或顶层字符串、数组不会被偷偷当成空参数执行。

危险动作在等待确认时已经预留一次，用户批准后只结算这次预留，不重新扣减，也不重建整份预算。审批仅覆盖显示的动作；同一模型批次中未被保留的其余提议计为未执行，由模型看到结果后重新评估，不会悄悄一起执行。后续审批仍遵循各入口原有的授权边界，桌宠继续逐项确认。

用尽预算后，运行器停止外部动作；若本轮启用了 `update_plan` 且仍有计划额度，模型可以更新本地计划后总结。这个控制工具只写本轮元数据，不消耗外部动作次数，也不计为成功动作。提供商继续提议外部工具仍不会执行，并在回执中记录略过数量。恰好执行完允许的动作、没有已知错误或遗漏时，可以正常结束并说明按预算收尾；预算用尽本身不等于任务失败，也不证明业务目标已经完成。

v0.34 起，API 工具循环最多15次模型调用，包含最后一次禁用工具的总结，跨审批保留；计划更新尝试另限8次。前置检索和底层网络重试不计入这个循环上限。模型报告的计划和这里的执行事实各自保存，详见[任务计划卡](agent-task-plans.md)。

## 如何归纳结果

- 只有失败或拒绝、没有成功返回的工具：执行失败。
- 既有成功返回，又有失败、拒绝或已知遗漏：需要核对，保留已得到的结果。
- 连续重复调用或循环上限触发：明确停止原因，不能冒充自然完成。
- 预演只记录计划调用，没有实际执行；预演次数与成功次数分开。
- 取消或租约中断：保留已知次数，未确认的预留仍表示不明结果，不能推断「没有发生」。

「成功返回」仅表示处理器正常返回且没有明确错误标志；MCP 的显式错误结果会计为失败。运行器不会推断任意业务数据里的 `status` 字段，也不能独立核验网页内容真实性、模型回答准确率或用户最终目标。即使后续找到了替代结果，发生过的失败仍保留在回执中，便于核对。

## 旧审批与异常

新审批保存完整计数和重复调用签名。旧审批没有账本时，只能从已保存的 assistant/tool 成对记录重建已消耗次数，并匹配当前待确认动作。记录损坏、不完整、超过原预算或无法证明对应关系时拒绝执行，保留当前审批供取消后重新发起；不会猜测剩余次数。

工具已执行后，提供商再报告不支持函数调用，不会转入关键词备用路径重复做事。外层模型或运行器异常会将已有回执标记为异常结束，保留已知结果。运行器崩溃后仍沿用可靠任务模块的中断策略，不自动重跑不明动作。

本模块的预算及回执只覆盖 API 函数调用循环。CLI、工作流与关键词备用路径保留各自的执行规则，没有回执时明确显示未记录，不能据此声称它们受到 API 六步预算约束。
