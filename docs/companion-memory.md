# 彩宝的记忆小本

记忆小本让用户查看、保存和修正 API 伙伴会参考的资料。它不需要生成模型完成管理操作，也不会从普通闲聊中自动推断并保存长期事实。

## 日常使用

在桌宠聊天区打开「记忆小本」。没有对话时会先创建一段自己的对话，以确定记忆所在空间。

- 手动填写标题和正文后，点保存才会创建卡片。用户消息旁的「存到记忆」只填入可编辑草稿，仍需明确保存。
- 记忆卡可以修改、暂停、恢复或删除；过期卡会单独标明。删除这张卡也会移除它的检索向量，不会自动删除原聊天。
- 能取得且属于当前对话的来源消息可以展开预览；来源不可用时只说明不可用，不补造原文。
- 个人全局卡与当前空间的卡放在同一列表，分别标明范围；较多记录按页加载。
- 「相处方式」「长期记忆」「近期上下文」是另一层背景文本，也可以查看、修改或清空。近期上下文编辑不改变内部的近期轮次记录。

新对话仍会保留同一空间的记忆。聊天记录、记忆卡和背景文本分别存储；旧对话仍可能包含曾经说过的内容。想让接下来的回答避开旧聊天，可以开始新对话；不要把删除一张卡理解为清除了所有记录。

## 什么会进入回答

「回答时参考我的记忆」控制后续 API 任务的记忆读取。开启时，角色背景、长期文本和近期摘要分别有字符上限；记忆卡按当前任务检索，管理列表中的卡片不保证每次都被选中。关闭会跳过这些记忆和记忆工具，但保留当前对话的正式上下文。

背景文本作为有来源的资料进入提示，不能为工具授权、代替当前用户要求或覆盖运行时约束。卡片状态、有效期和所有权同时参与检索；编辑正文会更新向量和摘要，避免检索继续返回旧正文的摘要。

CLI 后端使用自己的原生会话与工具，不注入这套 API 记忆。小本仍可管理资料，但不表示已经修改或清除 CLI 的原生上下文。

## 什么时候写入

桌宠的长期记忆只在用户直接保存，或明确批准记忆工具时写入。桌宠任务完成事件带有渠道标识，自动整理观察者会跳过 `companion`，不在几轮闲聊之后额外调用生成模型或产生未经查看的长期事实。正式聊天依旧进入自己的会话历史。

原有工作台、QQ 等其他渠道保持既有自动整理行为。这些渠道生成的背景同样可能出现在当前空间的小本里；它们的读改写与手工编辑共用文件锁，避免覆盖编辑期间的新文本。

记忆卡创建或修改正文会使用现有 embedding 配置更新检索索引。如果配置了远程 embedding，它可能需要网络并产生相应费用；默认 mock embedding 不属于真实语义检索。记忆管理本身不调用生成模型。

手动保存和批准记忆工具使用同一条写入路径。卡片与检索向量一起提交，向量生成失败时一起回滚；更正失败保留旧正文和旧索引，避免新正文配上旧检索结果。

## 失败与并发

写入不会自动重试。响应丢失时保留草稿并只读刷新，让用户先核对列表；不把连接错误显示为“已经记住”。文档使用内容版本和稳定旁路文件锁，两个编辑器不能悄悄覆盖彼此；版本冲突后保留草稿并展示最新内容，必须重新核对再保存。

账号或对话切换会清空面板，旧请求回调不能把上一位用户的内容写回。服务端从登录身份与已验证对话确定空间，不接受客户端指定任意用户或空间。

数据库卡片与 Markdown 文本仍是两个存储层，没有跨两者的统一事务；本模块按单张卡或单份文档进行明确编辑。已经启动的任务、旧审批和原有历史不会因为编辑小本而被重新执行或重写。
