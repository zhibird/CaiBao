# 可靠任务：执行、事件与桌宠恢复

彩宝的任务不应随着一条浏览器连接消失。此模块将排队任务的执行交给后台运行器，聊天页和桌宠只观察同一份持久记录；刷新、重连、打开任务历史不创建另一份执行。

## 产品约束

- 每次提交具有稳定的 `client_request_id`。同一用户用相同标识和参数重试，得到原任务；同标识改参数会被拒绝。
- 一个任务只能被一个后台执行器接管；并发观察者共享结果。同一对话的托管任务共用执行槽，API、CLI 和审批续接不会并行改动同一轮上下文。
- 停止观察不停止任务。停止任务是独立、明确的动作，沿用工具边界上的协作式取消。
- 每次确认绑定当前待执行操作及其模型回合。旧确认不能授权下一次写入，哪怕内容完全相同。
- 服务器失去任务所有权时，记录中断并保留现有事件、部分文字和步骤；不能自动重放结果未知的外部操作。
- 桌宠恢复进度时不重播旧回复，不以朗读状态覆盖正在执行的任务状态。历史任务只读查看。

## 后台执行与持久日志

`AgentRunRuntime` 使用有界线程池与队列，工作线程自行创建、关闭数据库会话，不持有 HTTP 请求的数据库对象。运行器把源 Agent 事件写入 `agent_run_events`，数据库生成的全局整数作为游标；每个任务中的顺序递增，其他任务造成的游标空隙是正常现象。

事件写入在分配游标前串行锁定对应任务，避免并发快照先提交较大的游标、导致重连跳过较小事件。模型事件原本的局部 `seq` 不再承担重放顺序。

`agent_run_workers` 保存唯一所有者、租约和 CLI 对话占位。独立心跳线程在模型或工具等待期间续租；只有租约过期的任务会被接管为“已中断”，其他仍在线的服务进程不受影响。已经持久化到等待确认状态的任务可以在租约过期后继续接受当前操作的精确授权。

CLI 租约过期不能证明其子进程已经退出，因此会保留该对话的工作区占位，禁止新任务或审批续接抢占。原所有者结束执行、返回现有子进程清理流程后才释放占位；清理抛出异常时仍保留。如果原服务永久丢失，当前保守策略保留阻止状态，可以新建对话使用独立工作区。现有清理使用进程组 TERM／KILL 和有界等待，尚未提供独立进程监督或跨进程的遗留 CLI 自动回收。

运行器也包住执行前的模型路由、插件和初始化错误。异常会留下可解释的失败记录，不能永久卡在“进行中”。旧执行器恢复后，取消和中断状态阻止它继续后续工具或覆盖终态。

正常关闭会等待已开始的调用返回，未开始的排队工作会留下中断记录。同步网络／工具调用仍受各自超时控制，本模块不宣称能撤销已发生的外部副作用。事件日志当前保留全部记录，尚无自动清理策略。

## API

所有入口继续使用登录用户的身份，不能读取、启动或确认其他用户的任务。

| 入口 | 行为 |
| --- | --- |
| `POST /api/v1/agent/runs` | 持久化排队任务；可携带 `client_request_id`，不会因重复提交产生另一条任务。 |
| `POST /api/v1/companion/runs` | 使用桌宠的交互和后端策略创建同样的任务。 |
| `POST /api/v1/agent/runs/{id}/start` | 显式请求后台执行；重复调用不再次执行。 |
| `GET /api/v1/agent/runs/{id}/stream` | 为旧客户端保留排队任务的首次调度行为，随后只观察持久事件；断线不关闭执行器。 |
| `GET /api/v1/agent/runs/{id}/events?after=0&limit=100` | 只读事件分页，返回 `items`、`next_seq`、`status`、`has_more`；不会调度任务。 |
| `GET /api/v1/agent/runs?conversation_id=...&trigger_channel=companion` | 当前用户的任务列表，最近任务在前。 |
| `POST /api/v1/agent/runs/{id}/confirm` | 桌宠必须携带本轮 `approval_token`；验证后由后台线程执行，HTTP 观察者离开不会撤销已经给出的授权。 |
| `POST /api/v1/agent/runs/{id}/cancel` | 取消排队或待确认任务；运行中的 API Agent 在下一工具／模型边界停止。 |

SSE 帧包含 `id` 和 JSON 中相同的 `seq`。客户端以 `Last-Event-ID` 或 `after` 指定最后看过的游标，服务端仅返回更晚事件；空闲时发送注释心跳。任务历史查询必须使用只读入口，不能为了展示记录而打开一个尚未执行任务的兼容流入口。

生产依赖创建的 `AgentService.run()` 也使用托管执行，因此同步 `/agent/run` 与 App 调用共享后台所有权和会话互斥；同步入口仍使用原有 completion 协议，等待最终结果。直接手工创建、未注入运行器的服务实例保留独立同步执行，适用于已有内部集成，但不宣称具有托管租约保证。对于没有托管所有权的旧“进行中”任务，只报告现状，不擅自接管或重试。

## 桌宠交互

前端在发送前保存本次提交标识和不可变参数。创建响应丢失时，先查服务器任务列表，再沿用原标识核对，不能重新生成标识。刷新时先重放事件，再订阅后续游标；如果结果不明，暂停下一次提交并提供重新核对入口。

任务记录显示进行中、等待确认、完成、部分完成、失败、停止与中断，工具结果与文字都从持久事实恢复。查看过去的排队任务不会自动执行；缺少本地准入记录的排队任务保留供核对或取消。

恢复回调带有观察代次，退出账号或切换对话后，旧请求不能把旧任务写回当前界面。模型输出仍使用纯文本，不把回复作为网页代码执行。

## 参考

参考用户提供的 shi-xi 关于执行所有权与界面事实投影分离的高层思路；没有复制其私有实现或内部文档。公开参考为 [Goose 的会话事件路由](https://github.com/aaif-goose/goose/blob/main/crates/goose-server/src/routes/session_events.rs)：将任务提交、后台执行、事件观察、重连游标分开。CaiBao 的实现保留自身 FastAPI／SQLAlchemy／工具审批模型。

## 验证范围

运行器测试覆盖无观察者执行、观察者断开、多个观察者、跨运行器认领、过期租约、慢工具期间续租、CLI 会话互斥、错误收敛、排队关闭及待确认恢复。接口测试覆盖只读事件、游标、权限、响应丢失后的幂等重试和精确审批竞争。前端用真实 `ReadableStream` 分片验证重连、文字去重、任务发现、只读历史、有限重试和旧账号回调抑制。

测试使用本机假模型／CLI，不读取订阅凭证、不消费真实 API 额度，也不需要显示桌宠窗口。
